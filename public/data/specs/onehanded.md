# Однорука схема керування для 2D веб-гри водіння (портрет, смартфон)

## 1. Огляд референсів — як це реально роблять

| Гра / жанр | Схема | Придатність під одну руку |
|---|---|---|
| **Traffic Rider, Moto Rider** | нахил пристрою (accelerometer) керує нахилом мотоцикла, газ — окрема кнопка правим великим пальцем | добре, але потребує калібрування нахилу і псує гру, якщо телефон лежить на столі |
| **Crossy Road, Subway Surfers** | свайпи/тапи ліворуч-праворуч = дискретна зміна смуги, автобіг вперед | ідеально під одну руку, але дає лише дискретний (лейновий), не плавний рух |
| **Hill Climb Racing** | 2 великі кнопки на весь екран (газ праворуч, гальмо/назад ліворуч), нахил кузова — фізика | двома руками за задумом, боком лежачи — під один палець теж працює, бо кнопки величезні |
| **Real Racing, Asphalt (touch-steer режим)** | віртуальне кермо-джойстик під великий палець знизу, авто-газ | одна рука — базовий сценарій цих ігор |
| **Race Master 3D, Zigzag/2048-стиль раннери** | drag/hold пальцем в будь-якій точці екрана — X-координата пальця = X-позиція машини (1:1 mapping), газ завжди максимальний | найкраще для однієї руки: не треба точно попадати в зону кнопки, все відбувається великим пальцем без переносу руки |
| **Deer Hunter/тир на рейках** | тап ліворуч/праворуч від центру екрана = дискретний поворот у той бік | простий fallback, погана точність на швидких поворотах |

**Висновок з ринку:** топові однорукі driving/racer-и на телефоні майже завжди зводяться до **однієї з двох механік**:
- **A. "Drag-to-position"** — палець торкається будь-де в нижній половині екрана й перетягується; горизонтальна координата пальця напряму мапиться на позицію/кут керма машини. Газ автоматичний.
- **B. "Virtual thumb-wheel"** — фіксована зона (зазвичай нижній правий/лівий кут) із віртуальним диском/повзунком, який великий палець крутить/тягне для повороту; газ теж автоматичний або утримується тим самим пальцем через вертикальну складову жесту.

Нахил (deviceorientation) як **основний** метод для one-hand на смартфоні в портреті — погана ідея: гравець тримає телефон у руці, тому нахил тіла руки й корпусу конфліктує, немає стабільного "нуля", в транспорті/лежачи не працює. Тому tilt варто лишити **опційним альтернативним режимом**, не основним.

## 2. Обраний варіант

**Варіант A з елементами B: "Drag-anywhere steering + автогаз", з видимою підказкою-зоною знизу.**

Чому саме він, а не chat GPT очевидний "джойстик у кутку":
- Портретна орієнтація смартфона = вузький екран (~360–430px завширшки). Великий палець руки, що тримає телефон знизу, фізично дотягується практично до всієї нижньої половини екрана — тобто зона взаємодії природно велика, і не варто обмежувати її маленьким віртуальним колом 80×80px у кутку (типова помилка джойстиків — палець "з'їжджає" за межі зони й керування губиться).
- Абсолютний drag-to-position (палець ліворуч = машина ліворуч) дає гравцю миттєвий, передбачуваний зв'язок дотику з результатом — на відміну від відносного джойстика, де треба спершу "натиснути", відчути напрямок, потім керувати дельтою. Для казуальної/навчальної гри (ваш кейс — навчання ПДР) це знижує поріг входу.
- Газ автоматичний повністю знімає потребу в другій кнопці — критично важливо, бо саме так вирішується "одна рука, одна дія": палець ЗАВЖДИ відповідає тільки за напрямок, ніколи не перемикається між "газ" і "кермо".
- Гальмо не потрібне як окрема кнопка в arcade-режимі — гальмування відбувається автоматично при наближенні до перешкоди/стоп-лінії (game-design рішення, узгоджене з тим, що ваша гра вже вчить ПДР через підказки, а не через мануальне гальмо).

## 3. Точний UX

### Розкладка екрана (портрет)
```
┌─────────────────────────────┐
│      ігрове поле / дорога    │  ~70% висоти — трафік, дорога, знаки, світлофори
│                               │
├─────────────────────────────┤
│   ЗОНА КЕРУВАННЯ (touch)     │  нижні ~30% висоти екрана
│  ← напівпрозора смуга-трек → │  (можна drag з БУДЬ-ЯКОЇ точки, не лише в межах смуги)
└─────────────────────────────┘
```

- Зона керування — **вся нижня третина екрана**, не малий джойстик. Це і є "one thumb zone" з вашого запиту.
- При `touchstart`/`pointerdown` у цій зоні: під пальцем з'являється легкий візуальний маркер (напівпрозоре коло), що показує поточну X-позицію "керма". Це дає тактильний+візуальний фідбек без потреби дивитись на палець.
- Рух пальця по X у межах зони → плавно (з інерцією/lerp, а не миттєво-різко) зсуває машину по X-осі дороги, з обмеженням у межах ширини проїзної частини.
- Якщо гра лейнова (3 смуги, як зараз у вашому SwiftUI-проєкті) — X-координата мапиться не напряму в піксель, а в "намір": перетин порогової відстані (~15% ширини зони) від центру ініціює зміну смуги ліворуч/праворуч, з дебаунсом ~150–200мс, щоби палець, що трохи тремтить, не смикав машину між смугами.
- Якщо гра з вільним рулінгом (open-lane) — X-координата пальця мапиться напряму (1:1 або з невеликим множником чутливості) в X-позицію машини, з clamp по краях дороги.
- `touchend`/`pointerup` (палець відпущено) → кермо плавно повертається в центр (return-to-center твін, ~200мс ease-out), машина продовжує їхати прямо. Це важливо: не "заморожувати" останню позицію, бо гравець забуде де був палець.
- Газ: **завжди автоматичний**, керується через `requestAnimationFrame`/game loop незалежно від input — базова швидкість або cruise control з невеликим прискоренням на прямих і сповільненням у поворотах/перед перешкодами. Гравець фізично не може натиснути "газ" — його там немає.
- Гальмо: автоматичне сповільнення-подія (перед стоп-лінією, перед пішоходом на зебрі) — рушій гри сам знижує швидкість до 0 або до безпечної, без участі пальця. Опційно: **довге утримання (long-press, без руху по X)** може трактуватись як "ручне екстренне гальмо" — необов'язкова фіча, не критична для MVP.
- Мультитач: ігнорувати другий палець (щоб випадковий дотик другою рукою/щокою не зламав керування) — слухати лише перший активний `pointerId`.

### Ергономіка під великий палець правої/лівої руки
- Зона керування розтягнута на всю ширину екрана знизу — і праворуч, і ліворуч тримача телефону однаково зручно, бо великий палець працює по дузі знизу-вгору-в сторони незалежно від того, в якій руці телефон.
- Немає фіксованих кнопок у кутках (типова помилка — кнопка в дальньому від великого пальця куті недосяжна). Кермо йде за пальцем, а не навпаки.
- Візуальні елементи UI (пауза, підказки ПДР) розміщати **над** зоною керування або в самих верхніх кутках — поза досяжністю великого пальця, щоб не заважали й не провокували випадкові тапи.

## 4. Перемикання «одна рука» ↔ «дві руки»

Пропозиція — **не окремий екран налаштувань посеред гри**, а перемикач у меню перед стартом заїзду (та доступний з паузи):

- **Одна рука (за замовчуванням для мобільних)**: тільки drag-to-steer описаний вище, автогаз, без кнопок гальма/газу.
- **Дві руки (класична)**: те, що вже реалізовано у вашому SwiftUI-проєкті — окремі кнопки ← / → (зміна смуги) ліворуч знизу, Газ/Гальмо праворуч знизу, під дві руки або два пальці однієї руки в landscape. Корисно на планшеті або коли гравець хоче ручний контроль швидкості (важливо саме для навчання гальмування перед пішоходом/на червоне — тут ручне гальмо педагогічно цінне).
- Автовизначення підказки при першому запуску: якщо ширина екрана < ~500px і orientation = portrait → пропонувати one-hand за замовчуванням; якщо landscape або планшет → two-hand. Але завжди залишити явний перемикач у налаштуваннях, збережений у `localStorage`.
- Перемикання не вимагає перезапуску гри — контролер вводу підписаний на loop гри як окремий модуль (`InputController`), який просто міняє джерело подій.

**Про КПП/передачі**, як ви й зауважили: механіка ручної КПП (окрема кнопка switch-gear, або свайп вгору/вниз для передач) органічно **несумісна з one-hand-режимом**, бо додає третій "канал" вводу (напрям + газ/гальмо + передача) — а великий палець фізично не може одночасно рулити й перемикати передачі. Тому:
- **One-hand режим = завжди автомат** (auto-gas, без ручної КПП). Це не спрощення заради лінощів, а єдиний ергономічно чесний варіант.
- **Ручна КПП доступна тільки в two-hand режимі**, де друга рука/палець вільна під окрему кнопку передачі.
- В UI варто явно писати "Одна рука = автомат" при виборі режиму, щоб не було очікування ручного керування передачами там, де воно неможливе.

## 5. Псевдокод

### 5.1. Основний обробник Pointer Events (drag-to-steer)

```js
class OneHandSteering {
  constructor(controlZoneEl, car, opts = {}) {
    this.zone = controlZoneEl;          // DOM-елемент нижньої зони керування
    this.car = car;                     // об'єкт машини гравця { x, targetX, laneMode }
    this.activePointerId = null;
    this.centerX = 0;                   // X центру зони на момент touchstart
    this.currentDragX = null;
    this.sensitivity = opts.sensitivity ?? 1.0;
    this.laneMode = opts.laneMode ?? true;   // true = дискретні смуги, false = вільний рулінг
    this.laneChangeThreshold = opts.laneChangeThreshold ?? 0.15; // 15% ширини зони
    this.laneChangeCooldownMs = 180;
    this.lastLaneChangeAt = 0;

    this.zone.addEventListener('pointerdown', this.onPointerDown.bind(this));
    this.zone.addEventListener('pointermove', this.onPointerMove.bind(this));
    this.zone.addEventListener('pointerup', this.onPointerUp.bind(this));
    this.zone.addEventListener('pointercancel', this.onPointerUp.bind(this));
  }

  onPointerDown(e) {
    if (this.activePointerId !== null) return;      // ігноруємо другий палець
    this.activePointerId = e.pointerId;
    this.zone.setPointerCapture(e.pointerId);
    const rect = this.zone.getBoundingClientRect();
    this.centerX = e.clientX;                        // точка захвату = "нуль" керма
    this.zoneWidth = rect.width;
    this.currentDragX = e.clientX;
    this.showThumbMarker(e.clientX, e.clientY);
  }

  onPointerMove(e) {
    if (e.pointerId !== this.activePointerId) return;
    this.currentDragX = e.clientX;
    const deltaX = (e.clientX - this.centerX) / this.zoneWidth; // -1..1 нормалізовано
    this.updateThumbMarker(e.clientX, e.clientY);

    if (this.laneMode) {
      this.handleLaneIntent(deltaX);
    } else {
      const normalized = clamp(deltaX * this.sensitivity, -1, 1);
      this.car.targetX = roadCenterX + normalized * (roadWidth / 2 - car.halfWidth);
    }
  }

  handleLaneIntent(deltaX) {
    const now = performance.now();
    if (now - this.lastLaneChangeAt < this.laneChangeCooldownMs) return;
    if (deltaX > this.laneChangeThreshold) {
      this.car.changeLane(+1);
      this.lastLaneChangeAt = now;
      this.centerX = this.currentDragX;   // ре-центрування — щоб не треба тягнути далі й далі
    } else if (deltaX < -this.laneChangeThreshold) {
      this.car.changeLane(-1);
      this.lastLaneChangeAt = now;
      this.centerX = this.currentDragX;
    }
  }

  onPointerUp(e) {
    if (e.pointerId !== this.activePointerId) return;
    this.activePointerId = null;
    this.hideThumbMarker();
    if (!this.laneMode) {
      // плавне повернення керма в центр (не миттєве)
      this.car.targetX = lerpToLaneCenter(this.car.targetX, 200 /*ms*/);
    }
  }

  // Газ і гальмо НЕ підключені до цього класу — вони живуть у GameLoop.autoThrottle()
}
```

### 5.2. Автогаз/автогальмо у ігровому циклі (незалежно від input)

```js
function autoThrottle(car, roadState, dt) {
  const hazardAhead = roadState.nearestHazardDistance(car); // стоп-лінія, пішохід, авто попереду

  let targetSpeed = car.cruiseSpeed;
  if (hazardAhead.distance < hazardAhead.safeBrakingDistance) {
    targetSpeed = hazardAhead.requiresFullStop ? 0 : hazardAhead.safeSpeed;
  }

  // плавне прискорення/гальмування, а не стрибок
  const accel = targetSpeed > car.speed ? car.accelRate : car.brakeRate;
  car.speed = moveTowards(car.speed, targetSpeed, accel * dt);
}
```

### 5.3. Опційний tilt-режим (deviceorientation) — альтернатива, не основний спосіб

```js
class TiltSteering {
  constructor(car) {
    this.car = car;
    this.calibrationGamma = null;   // нуль-точка калібрується під поточний хват телефону
    this.enabled = false;
  }

  async requestPermission() {
    // iOS 13+ вимагає явного дозволу користувача, викликати з жесту (клік по кнопці "увімкнути нахил")
    if (typeof DeviceOrientationEvent?.requestPermission === 'function') {
      const state = await DeviceOrientationEvent.requestPermission();
      if (state !== 'granted') return false;
    }
    window.addEventListener('deviceorientation', this.onOrientation.bind(this));
    this.enabled = true;
    return true;
  }

  calibrate(currentGamma) {
    this.calibrationGamma = currentGamma;   // "тримаю зараз рівно" = центр
  }

  onOrientation(e) {
    if (!this.enabled || this.calibrationGamma === null) return;
    const gamma = e.gamma; // ліво-право нахил, -90..90
    const delta = clamp((gamma - this.calibrationGamma) / 25, -1, 1); // 25° = повний замах
    this.car.targetX = roadCenterX + delta * (roadWidth / 2 - car.halfWidth);
  }
}
```

Ключове застереження до tilt: обов'язкова кнопка "Відкалібрувати" (перевизначити нуль) прямо в грі, бо кут утримання телефона однією рукою в кожного різний і "пливе" з часом.

## 6. Підсумкова рекомендація для вашого проєкту

Зараз у `KotikPDR/Features/Game/GameEngine.swift` та `GameView.swift` реалізована лейнова (3-смугова) SwiftUI-версія з дискретними кнопками ← → і окремим газ/гальмо. Якщо плануєте веб-версію або переробку мобільного керування:

1. Лейновий рух вже добре лягає на **drag-to-steer з пороговим intent** (п. 5.1, `laneMode: true`) — не треба міняти геймдизайн смуг, лише замінити кнопки ← → на one-finger drag по нижній зоні.
2. Газ/гальмо перенести в `autoThrottle()` (п. 5.2), прибравши кнопки Газ/Гальмо з мобільного UI, лишивши їх тільки для macOS-клавіатури/two-hand режиму (`↑`/`↓`/`W`/`S` вже є — це і є ваш "two-hand" fallback, залишити як є).
3. Додати перемикач "Одна рука / Дві руки" в налаштування гри, за замовчуванням one-hand на iPhone-портреті.
4. Ручну КПП не додавати взагалі, поки основний режим one-hand — вона суперечить обраній схемі; якщо потрібна для педагогічної цінності (навчання передач), вона можлива тільки в two-hand режимі окремою кнопкою.
